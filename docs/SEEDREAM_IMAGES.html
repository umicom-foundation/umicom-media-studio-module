Create a Seedream image in Umicom Media

The Seedream images page creates one image from a written description. It uses BytePlus ModelArk, then keeps the returned image in memory for preview and PNG export. A PNG is an image file that preserves detail without lossy compression.

Before you start

You need a ModelArk API key, API access to a model or endpoint that supports PNG output, and the provider's required credit or billing arrangements. Check these in your BytePlus account. A Lumina subscription alone does not establish that the same account can make ModelArk API requests. This page uses the Asia-Pacific ModelArk destination shown in the request review. It does not sign in to Lumina or manage team seats.

Your build must include the optional HTTP and PNG adapters. If they are unavailable, the page can prepare a review but cannot generate an image.

Generate and save an image

  1. Open the Media creative workspace and select Seedream images.
  2. Select Manage local profile and API keys. Create or open your local profile and save your ModelArk key under the alias byteplus-modelark. An alias is a local name for a key; it is not the key itself. The profile password unlocks local access and is not sent to BytePlus.
  3. Return to the image page. Enter the local profile password and copy the model or endpoint ID from your ModelArk account. Choose one that supports the PNG output requested by this page.
  4. Write a prompt describing the subject, setting, composition, lighting and intended use. For example: “A quiet library with tall windows, soft afternoon light, a wide composition with clear space for a tutorial title.” Prompts can contain multiple lines.
  5. Select Review image request. Read the destination, local account alias and exact request. No network request has been sent at this point. Changing the prompt, model, alias or password retires this review and its approval.
  6. If the request is correct, select its approval checkbox and then Generate reviewed image. This sends the prompt and model settings to BytePlus and may incur a provider charge. The page requests one watermarked PNG at the provider's 2K size setting; the provider chooses its exact dimensions.
  7. Wait for the preview. Work runs in the background, and the password field is cleared after the request starts. The result is not automatically written to disk or attached to your project.
  8. Enter a full path ending in .png in an existing folder, then choose Save new PNG. For example, use a new filename in your Pictures folder. Existing files are never replaced. A successful export reports the new file path.
  9. To use that file in other creative work, open the existing Assets page and capture it. Automatic timeline insertion is a separate workflow and is not performed here.

Recover from an interrupted request

Stop local work stops waiting or exporting locally. It cannot undo an image generation already accepted by the provider. A timeout, connection failure or cancellation may still incur a charge. Check your BytePlus usage before preparing another request, then acknowledge that check on the page. Requests are never automatically retried.

If saving reports that a new file was retained after an error, inspect that file before using it: an interrupted write may be incomplete. Choose a different filename to try again. The in-memory image remains available after an export failure while this page stays open.

Privacy and current boundaries

Keys use Framework's local profile credential service. They are not saved in this page's request, image, project or repository. Sending a request still sends your prompt and settings to the provider, under its service and data policies. This is remote generation, not local inference.

The page accepts text only. Reference-image upload, image masks, transparent-background requests, multiple outputs, layer decomposition, video generation and durable generation history are not offered by this page. Save a result before generating a replacement or closing the page; unsaved images are not recovered after restart. Responses over the local memory limits are refused even if the provider generated them.

For provider setup and compatible model capabilities, consult the official image API reference. Model availability and account permissions are checked by BytePlus.
